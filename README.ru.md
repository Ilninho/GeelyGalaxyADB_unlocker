# Geely Galaxy ADB unlocker — разработка

Это локальный вариант проверенной схемы `GeelyGalaxy_ADB` с подменой DNS и
MQTT-брокером. Исходники и процесс сборки одного исполняемого файла готовы,
но **проверки на Windows и на машине пока не проводились**.

## Планируемая схема

1. Программа на Windows пытается включить мобильную точку доступа, если она
   ещё не работает.
2. Головное устройство подключается к ней по Wi-Fi. USB-кабель к ноутбуку
   не обязателен: `adb devices -l` — дополнительная проверка, если кабель есть.
3. DNS на ноутбуке направляет только `oneoss-ecu-mqtt.geely.com` на локальный
   адрес ноутбука. Остальные запросы проходят к обычному DNS.
4. Локальный MQTT/TLS-брокер слушает TCP 8883 и после подключения ГУ
   отправляет существующую команду `ADBSwitch=ON`.
5. При штатном завершении программа возвращает прежний режим IPv4 DNS и адреса
   серверов, удаляет только свои правила брандмауэра. Снимок сохраняется до
   изменений; после аварийного закрытия программа повторит восстановление при
   следующем запуске. Немедленное восстановление после жёсткого завершения
   процесса или отключения питания пока не гарантируется.

Главный файл — `unlocker.py`. В Linux и macOS пока доступен только режим
`--broker-only`: точку доступа и DNS там нужно настроить вручную.

## Сертификат TLS

На P145 / IHU039G установленный `CloudAuthService` проверяет доверие к
сертификату MQTT-сервера, хотя проверка имени сервера отключена. Сертификат,
самостоятельно выпущенный программой на Windows, машина автоматически не
примет. Проверенный вариант с VPS использовал сертификат общедоверенного УЦ.

Рекомендуемый вариант — отдельное бесплатное имя, например на dynv6 с
отдельным почтовым ящиком проекта, и общедоверенный сертификат. dynv6
позволяет подтвердить выпуск сертификата через TXT-запись DNS-01. Токен этого
отдельного аккаунта нужен только автору
при выпуске и продлении сертификата: в программу он не встраивается, доступ к
`ilninho.xyz` не нужен. Пользователю не понадобятся домен, токен, Python или
VPS во время работы. Публичная A-запись для машины не нужна: DNS на ноутбуке
направляет нужное имя MQTT на локальный адрес точки доступа. Автор задаёт
сертификат и ключ в секретах GitHub Actions, обновляет сертификат и
пересобирает файлы до истечения срока.
**Встроенный в публичный файл закрытый ключ может извлечь любой получатель.**
Поэтому нужен отдельный ключ только для этой программы; ключ действующего
сайта или старого VPS использовать нельзя. Токен DNS-провайдера хранится
отдельно
от репозитория и EXE и управляет только выделенным бесплатным именем.

Текущий сертификат для `geely-unlocker.dynv6.net` выпущен Let's Encrypt через
DNS-01 с RSA-ключом и цепочкой до ISRG Root X1. Он действителен до 9 января
2027 года. Токен DNS-провайдера и закрытый ключ не хранятся в Git. Автору
понадобится обновить сертификат и пересобрать программу до этой даты. Доверие
к цепочке на самом ГУ ещё нужно проверить на машине.

Другие варианты: сертификат пользователя через `--cert` и `--key` либо
предварительная установка локального корневого сертификата на ГУ. Просто
выпустить самоподписанный сертификат на ноутбуке недостаточно.

## Запуск и сборка

При разработке: `python unlocker.py --cert <fullchain.pem> --key <privkey.pem>`
из консоли администратора Windows. Программа попытается включить точку доступа.
Если Windows не разрешит это приложению, включите её в настройках и повторите
запуск. На Linux/macOS пока используйте `--broker-only` с ручной настройкой
Wi-Fi и DNS.

Для выпуска одного файла задайте в GitHub секреты `TLS_FULLCHAIN_PEM` и
`TLS_PRIVATE_KEY_PEM` — цепочку PEM-сертификата и ключ в формате PEM. Затем
вручную запустите workflow **Build standalone executables**. Артефакты
содержат Python внутри: пользователю ничего устанавливать не нужно. Windows,
Linux и macOS собираются отдельно. Локальный macOS-файл собран и прошёл
TLS-проверку. [Первая сборка GitHub Actions](https://github.com/Ilninho/GeelyGalaxyADB_unlocker/actions/runs/38171781378)
успешно завершилась на всех трёх платформах. Скачайте [ZIP для Windows из предварительного релиза](https://github.com/Ilninho/GeelyGalaxyADB_unlocker/releases/download/v0.1.0-preview/GeelyGalaxyADBUnlocker-Windows.zip).
Внутри находится один 64-битный `GeelyGalaxyADBUnlocker.exe`; на Windows-сборщике он
запустился с `--help`. Работу точки доступа и подключение машины ещё нужно
проверить на Windows и в автомобиле.

В этом же релизе есть архивы для [Linux x86-64](https://github.com/Ilninho/GeelyGalaxyADB_unlocker/releases/download/v0.1.0-preview/GeelyGalaxyADBUnlocker-Linux.zip)
и [macOS arm64](https://github.com/Ilninho/GeelyGalaxyADB_unlocker/releases/download/v0.1.0-preview/GeelyGalaxyADBUnlocker-macOS.zip).
В каждом один исполняемый файл. Запускайте его с `--broker-only`; точку доступа
и DNS на этих системах пока нужно настроить вручную. Обе сборки прошли тесты
и запустились с `--help` на соответствующих сборщиках.

## Ручная настройка Linux

Нужны NetworkManager, Wi-Fi-адаптер с режимом точки доступа и доступ в интернет
через Ethernet или второй Wi-Fi-адаптер. Пакет с исполняемым файлом уже содержит
Python. Убедитесь, что установлен `dnsmasq` (в некоторых дистрибутивах пакет
называется `dnsmasq-base`): NetworkManager использует его для DHCP и DNS при
`ipv4.method shared`. Отдельную службу dnsmasq запускать не нужно. Путь
`/etc/NetworkManager/dnsmasq-shared.d/` поддерживается текущим NetworkManager,
но считается нестабильным интерфейсом; проверьте его для своей версии
([документация NetworkManager](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nm-settings-nmcli.html)).

1. Распакуйте Linux ZIP, откройте терминал в каталоге с файлом и выполните
   `chmod +x GeelyGalaxyADBUnlocker`. Команда `nmcli device status` покажет имя
   Wi-Fi-интерфейса. Ниже вместо `wlan0` укажите своё имя, а вместо пароля —
   свой пароль точки доступа. Сначала проверьте, что профиля `GeelyADB-AP` и
   файла `/etc/NetworkManager/dnsmasq-shared.d/geely-adb.conf` ещё нет: команды
   ниже предназначены для новой конфигурации и не должны заменять чужую.

   ```sh
   sudo nmcli device wifi hotspot ifname wlan0 con-name GeelyADB-AP ssid GeelyADB password 'your-wifi-password'
   sudo nmcli connection modify GeelyADB-AP ipv4.method shared ipv4.addresses 10.42.77.1/24
   sudo install -d /etc/NetworkManager/dnsmasq-shared.d
   printf '%s\n' 'host-record=oneoss-ecu-mqtt.geely.com,10.42.77.1' | sudo tee /etc/NetworkManager/dnsmasq-shared.d/geely-adb.conf
   sudo nmcli connection down GeelyADB-AP
   sudo nmcli connection up GeelyADB-AP
   ```

   IP `10.42.77.1` здесь выбран для новой
   сети; при конфликте с существующей сетью замените его **в обеих строках**.

2. Запустите брокер в этом терминале: `./GeelyGalaxyADBUnlocker --broker-only`.
   Разрешите входящие TCP 8883 и DNS UDP/TCP 53 в локальном файрволе для
   интерфейса точки доступа, если фильтрация включена. Подключите автомобиль
   к `GeelyADB` и при необходимости переподключите его, чтобы получить адрес и
   DNS по DHCP.
3. После сеанса остановите программу через Ctrl+C, затем удалите **только**
   созданные для этой инструкции профиль и DNS-файл:

   ```sh
   sudo nmcli connection down GeelyADB-AP
   sudo rm /etc/NetworkManager/dnsmasq-shared.d/geely-adb.conf
   sudo nmcli connection delete GeelyADB-AP
   ```

   Системный DNS ноутбука эти команды не меняют. Если до работы вы меняли
   другие сетевые параметры вручную, верните их отдельно.

## Ручная настройка macOS

Нужна локальная точка доступа/роутер, в которой можно задать DNS-сервер,
выдаваемый клиентам по DHCP. Mac и автомобиль должны быть в одной сети;
удобно подключить Mac к роутеру по Ethernet, автомобиль — по Wi-Fi. На роутере
отключите изоляцию клиентов, если она включена. Встроенная функция macOS
[«Общий интернет»](https://support.apple.com/en-qa/guide/mac-help/mchlp1540/mac)
может создать Wi-Fi-сеть, но не предоставляет документированной настройки DNS,
выдаваемого её DHCP-клиентам; одного включения этой функции для данной схемы
недостаточно. Ниже описан вариант с роутером, где эта настройка доступна.

1. Распакуйте macOS ZIP и выполните `chmod +x GeelyGalaxyADBUnlocker` в
   каталоге с файлом. Python для него не требуется. Закрепите за Mac постоянный
   адрес в LAN через DHCP-резервирование роутера, например `192.168.50.2`.
   Запишите прежнее значение DNS в настройках DHCP роутера и установите
   `192.168.50.2` как **единственный** DNS для клиентов. Адрес в командах ниже
   замените на фактический адрес Mac. Если роутер принудительно добавляет другой
   DNS или выдаёт DNS через IPv6, сначала отключите это на время сеанса.
2. Установите [dnsmasq](https://formulae.brew.sh/formula/dnsmasq) через
   Homebrew (`brew install dnsmasq`). Запустите его в отдельном терминале;
   **не** запускайте фоновую службу `brew services`:

   ```sh
   sudo "$(brew --prefix)/sbin/dnsmasq" --no-daemon --bind-interfaces --listen-address=192.168.50.2 --no-resolv --server=1.1.1.1 --host-record=oneoss-ecu-mqtt.geely.com,192.168.50.2
   ```

   `1.1.1.1` — пример вышестоящего DNS для остальных имён: при необходимости
   замените его своим. Если порт 53 уже занят другой службой, остановите её или
   используйте другой DNS-сервер; два процесса на одном адресе и порту не
   запустятся. Входящие DNS UDP/TCP 53 и TCP 8883 должны быть разрешены локальным
   файрволом.
3. Во втором терминале запустите `./GeelyGalaxyADBUnlocker --broker-only`.
   Подключите автомобиль к Wi-Fi роутера и переподключите его после изменения
   DHCP DNS. После сеанса остановите оба процесса через Ctrl+C, верните на
   роутере **записанное ранее** значение DHCP DNS и удалите временное
   DHCP-резервирование, если оно было создано только для этого сеанса.

## Проверка ручной настройки

До подключения автомобиля проверьте с **другого клиента той же Wi-Fi-сети**:
его DNS-сервер должен быть `10.42.77.1` (Linux) или адрес Mac (macOS), а
`nslookup oneoss-ecu-mqtt.geely.com` должен возвращать этот же адрес.
`nslookup example.com` должен по-прежнему разрешаться. Проверьте, что с клиента
доступен TCP 8883 на адресе ноутбука. Замена DNS или `/etc/hosts` **только на
ноутбуке** не направит трафик автомобиля к брокеру. При сетевой изоляции,
обходе локального DNS или выборе другого IPv6 DNS схема не сработает. Записи
`ADBSwitch=ON` и `execSuccess` в журнале брокера показывают обмен с ГУ, но
появление ADB следует проверять отдельно (например, `adb devices -l`, если
машина подключена по USB). Работа этих ручных схем на автомобиле пока не
подтверждена.

## Текущие проверки

`python -m unittest discover -v` проверяет DNS-маршрутизацию и восстановление
исходного DNS. Тесты не подтверждают работу точки доступа Windows, TLS-сеанс
с ГУ или появление USB ADB на машине.
