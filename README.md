# Geely Galaxy ADB unlocker — work in progress

This repository is the development copy of the verified `GeelyGalaxy_ADB`
MQTT/DNS approach. It is **not yet a working standalone Windows executable**.

## Intended local flow

1. A Windows laptop starts its Mobile Hotspot.
2. The head unit joins that hotspot over Wi-Fi. A USB connection to the laptop
   is optional and is needed only for an `adb devices -l` check.
3. A DNS resolver on the laptop maps only
   `oneoss-ecu-mqtt.geely.com` to the hotspot's local IPv4 address and forwards
   other names normally. The existing client still needs to be restricted to
   that name; it is retained here as a reference implementation.
4. An MQTT/TLS broker on the laptop listens on TCP 8883 and sends the existing
   `ADBSwitch=ON` command after the car authenticates and subscribes.
5. On exit, the program restores the adapter's previous DNS mode and addresses
   and removes only firewall rules it created. `windows_network.py` starts this
   exact DNS snapshot/restore work; it is not integrated yet.

The working remote-server sequence is documented in the original project.
`broker.py` and `client.py` here are copies of that baseline and must not be
mistaken for a finished local launcher.

## Current blocker: local TLS certificate

For P145 / IHU039G, the installed CloudAuthService uses the Android trust
store for its MQTT TLS connection. It disables hostname verification, but its
default X.509 trust manager still checks the certificate chain. A certificate
generated and self-signed on a user's Windows laptop is not automatically
trusted by the car. The original VPS succeeded using a publicly trusted
certificate. Therefore a self-signed local broker must first be tested on the
actual head unit; its success is not established by a local TLS test.

A generally deployable solution requires a trusted certificate obtained using
a domain controlled by someone, or an already trusted CA installed on the car.
Neither can be silently generated by a standalone EXE on an arbitrary laptop.

## Tests

Run `python -m unittest -v test_windows_network` to check the DNS restore logic.
These tests do not validate Windows hotspot behavior or an on-car TLS/MQTT
connection.
